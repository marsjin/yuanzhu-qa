## 1. 阶段目标与完成度

### 1.1 项目定位

面向单本长篇小说《遥远的救世主》的**资料查询型智能客服**。与通用聊天机器人的根本区别在于一条硬约束：

> 答案必须能被原著片段支撑；找不到依据就明确拒答并建议转人工，不得用通用知识冒充原文。

### 1.2 目标完成情况

| 目标 | 落地方式 | 状态 |

| 有据可查 | 混合检索 + 覆盖率门控，证据片段注入生成 | 已完成 |
| 不编造 | 引文 / 引用编号 / 专名 / 数字四类代码校验，修复只做减法 | 已完成 |
| 结构化问题可答 | 章节元数据导航、书目导览、原文摘录快路径 | 已完成 |
| 成本可控 | 快路径单次调用；Agent 路径硬上限 5 次、15 步；结构化问题 0 次调用 | 已完成 |
| 可对外服务 | FastAPI + SSE、登录会话、双角色、管理页、事件统计 | 已完成 |

## 4. 核心模块技术分析

### 4.1 检索层：双路召回与门控

**索引构建**
- 按 600 字切块、80 字重叠，保留 `chapter`、`chapter_seq`、`chunk_index` 元数据
- `doc_tokens()` 把章节标题并入检索词表，但**不改 `page_content`**，保证回答与摘录不出现人工前缀
- 索引与向量分别持久化为 `index.pkl` / `vectors.npy`，启动时直接加载

**打分与融合**
- BM25：`rank_bm25.BM25Okapi`，中文经 jieba + 领域词典分词
- 向量：fastembed + `BAAI/bge-small-zh-v1.5`，728×512 本地推理，不产生大模型调用
- 融合：RRF（k=60），只按名次合并，规避 BM25 分数与余弦相似度的量纲差异
- 排序修正：语义达标（≥0.55）的候选优先于纯词面命中，避免"词面重叠但答非所问"

**覆盖率门控**
```
coverage = Σ IDF(命中查询词) / Σ IDF(全部查询词)
```
- 未登录词（全书都没有）按 `log(N+1)` 上限计权，防止"内容/本书"这类泛词抬高覆盖率
- 判定：`coverage ≥ 0.5` 或 `semantic ≥ 0.55` → 允许作答；否则拒答
- 该机制解决了初版"第一章内容"等泛问法误判有据的问题（覆盖率 0.50 → 0.33）

**结构化导航**
- `chapter_seq_of()` 按标题中的章号反查 `chapter_seq`，不假设 `seq = 章号 - 1`（前言会导致错位）
- 支持"从第X章到第Y章"的范围检索，交由 Agent 路径处理

### 4.2 策略层：路由与校验

**意图路由（规则优先）**
- 顺序：转人工 → FAQ → 单章 → 书目导览 → 对比 → 情节 → 默认通用
- `chapter` 优先于 `plot`，避免"第一章讲了什么"被情节模板吞掉
- 聚合/多跳/章节范围/三实体以上 → 升级 Agent，避免规则模板硬凑

**答案校验（纯代码，不加模型调用）**
- 引文：`《书名》第X章` 必须命中证据来源
- 引用编号：`[E1]` 必须在证据集合内
- 专名：人物/别名/标签出现在答案但不在证据中 → 判为无支撑
- 数字：答案中的数字必须能在证据原文找到
- 修复策略：假引文替换为"（出处存疑）"，无支撑句尾追加"【大模型补充，非原文内容】"，**只做减法不做补写**

### 4.3 生成层：快路径与成本控制

| 问题类型 | 路径 | 模型调用 |
|---|---|---|
| 本书简介 | 档案 + 目录直接拼装 | 0 次（约 12ms） |
| 单章原文摘录 | 章内片段直接返回 | 0 次 |
| 单章摘要 | 章内均匀采样 6 段 + 单次生成 | 1 次 |
| FAQ / 购买 | 模板答案 | 0 次 |
| 通用 / 对比 / 情节 | 检索 + 单次生成 | 1 次 |
| 复杂聚合 | LangGraph 双环 | ≤5 次 |

`_spread()` 在章内均匀采样，避免只看开头漏掉本章后半段；情节梳理按章首片段等间隔抽样，拼出故事脊柱。

### 4.4 Agent 层：双环控制

LangGraph 十个节点：

```
understand → plan → act → grade ─┬─ synthesize → verify ─┬─ respond
                                 │                        ├─ repair → verify
                                 └─ rewrite → act          └─ refuse → respond
```

- 外环（补证据）：`grade` 不达标 → `rewrite` → `act`，最多 2 次
- 内环（修答案）：`verify` 不通过 → `repair` → `verify`，最多 1 次
- 硬上限：单请求 5 次模型调用、15 步图执行，防止循环与费用失控

### 4.5 数据与安全

| 项 | 设计 |
|---|---|
| 会话 | SQLite：`messages`、`session_state`、`events` |
| 登录 | HMAC 签名令牌（用户名\|角色\|过期时间），密钥由账号口令派生，改密码即失效 |
| 会话周期 | 60 分钟（`CS_AUTH_SESSION_MINUTES`） |
| 页面鉴权 | 浏览器页面只认 HttpOnly Cookie，未登录 303 → `/login`，退出立即失效 |
| 接口鉴权 | API 兼容 HTTP Basic（curl/脚本），Cookie 身份优先 |
| 角色 | admin 全部权限；user 仅对话与 `/health`；越权 403 |
| 账号 | 固定配置，不支持在线改密；`CS_AUTH_EXTRA_USERS` 可扩展 user 账号 |

### 4.6 运营与可观测

- 事件表按 `kind` 记录：`impression_default` / `click_default` / `impression_answer` / `click_answer`
- `/events/stats?days=N` 输出展示、点击、点击率；管理页可视化近 1/7/30 天
- 外链统一追加 `from` + UTM 参数，便于对方平台核对来路
- 反代场景信任 `X-Forwarded-For`，日志记录真实客户端 IP

## 5. 关键技术决策与取舍

| 决策 | 备选方案 | 选择理由 |
|---|---|---|
| 规则路由优先 | 全量 LLM 路由 | 省 1 次调用、结果稳定、可解释；复杂问题再升级 Agent |
| 本地小向量模型 | 云端 embedding API | 零调用成本、离线可复现；728 片段规模本地推理足够 |
| IDF 加权覆盖率 | 命中词数 / 全词数 | 泛词会稀释判定，加权后"内容/本书"不再独占权重 |
| 纯代码校验 | 再调一次模型做审稿 | 更快更省，且规则可回放；模型审稿本身也可能幻觉 |
| 单一 SQLite | PostgreSQL / Redis | 单机单实例足够；横向扩容前再迁移，避免过度设计 |
| 页面 Cookie + API Basic | 全部 Basic | Basic 无法可靠退出；Cookie 支持有效期与退出失效 |

## 7. 风险与遗留问题

| 风险 | 影响 | 应对计划 |
|---|---|---|
| 全量 50 条评测未跑完 | 指标仍为抽样结论 | 第二阶段补齐基线与回归门禁 |
| 抽象问法召回不足 | "结局"类问题可能拒答 | 人物档案作为证据注入、扩大同义改写 |
| 出处未强制 100% | 个别答案缺 `《书名》第X章` | 增加 citation presence 校验与重试 |
| "问错对象"未识别 | 如"丁元英的妹妹"覆盖率偏高 | 答案层增加人物关系断言校验 |
| SQLite 单机 | 无法多实例共享 | 预留 PostgreSQL/Redis 迁移 |
| 事件无清理策略 | 表持续增长 | 增加按天聚合与归档 |
